# VYRA known-answer vectors

Generated by `cargo xtask vectors`; checked by `cargo xtask vectors --check`
(gate F5 in `docs/CHECKS.md`). Do not edit by hand.

These vectors pin **VYRA's own v1 formats**: the hybrid KEM wire encoding and
combiner, the composite signature encoding, and the sealed box. They are not
vectors for ML-KEM, HQC, ML-DSA, Ed25519 or SLH-DSA themselves; component
conformance is tested separately (gate F4).

**HQC version.** The HQC component is `vyra-hqc`, an in-tree port of the HQC
v5.1 specification (reference tag `v5.1.0`) verified against the official v5.1
known-answer tests (`docs/DECISIONS.md` D-14). Every KEM and sealed-box vector
here depends on it. HQC is not yet a published FIPS standard; if FIPS 207
differs from v5.1, the VYRA wire version must be bumped and these vectors
regenerated.

## Files

| file | contents |
|------|----------|
| `kem.json` | VYRA-KEM-1/3/5: key generation, encapsulation, decapsulation; tampered-ciphertext (implicit rejection) vectors |
| `sig.json` | transition suites VYRA-SIG-2/3/5 (ML-DSA + Ed25519) and dual post-quantum suites VYRA-SIG-PQ1/3/5 (ML-DSA + SLH-DSA): key generation, signing, verification; tampered-signature and modified-message vectors |
| `seal.json` | sealed box over VYRA-KEM-1/3/5: seal and open; tampered-box and modified-AAD vectors |
| `combiner.json` | the KEM combiner on small explicit inputs |

## Format

- JSON, object keys sorted, two-space indentation, LF line endings, trailing
  newline. All byte strings are lower-case hex.
- Every suite has 5 vectors (`index` 0..4), except the dual
  post-quantum signature suites VYRA-SIG-PQ1/3/5, which have 2 (`index`
  0..1; vector 0 in full) because each SLH-DSA signature takes
  seconds to make and `--check` makes several per vector. Each vector has a `seed`.
  The procedure is listed in each file under `procedure`: a
  `DeterministicEntropy::from_seed(seed)` stream (SHAKE256 of a framed
  transcript, see `vyra_core::entropy`) supplies all randomness, in the order
  of the listed calls.
- Seeds are the ASCII strings `VYRA-KAT-v1/<kind>/suite-<id>/vector-<index>`
  (stored hex-encoded), `<kind>` one of `kem`, `sig`, `seal`.
- Keys, ciphertexts, signatures and sealed boxes are large, so every vector
  stores the **SHA3-256 digest of the complete wire encoding** (7-byte header
  `"VYRA" || 0x01 || object type || suite id` included) under `*_sha3_256`.
  32-byte shared secrets are stored in full.
- **Vector 0 of every suite stores every object in full** (`public_key`,
  `secret_key`, `ciphertext` / `signature` / `sealed_box`, wire encoding), so
  parsers can be tested against them.
- `negative` lists tampering vectors. KEM: flipping `xor_mask` at
  `wire_offset` of the ciphertext must decapsulate to `expected_shared_secret`
  (implicit rejection, never an error; D-02). Signatures and sealed boxes:
  the tampered object (or the modified message / AAD) must be rejected.
- Signatures: ML-DSA signing is **hedged** (FIPS 204). The 32-byte `rnd` is
  drawn from the same deterministic stream right after key generation, so the
  signatures are reproducible with that stream only; other randomness gives a
  different, equally valid ML-DSA half. The Ed25519 half is deterministic.
  The SLH-DSA half of a dual post-quantum suite is hedged as well (FIPS 205
  `addrnd`, n bytes drawn from the same stream after the ML-DSA `rnd`).
- Combiner: `output = SHA3-256(frame("VYRA-KEM-v1") || frame([suite_id]) ||
  frame(ss1) || frame(ss2) || frame(ct1) || frame(ct2) || frame(pk1) ||
  frame(pk2))`, `frame(x) = u64_be(len(x)) || x`. Each output is computed with
  `vyra_kem::combine` and independently by hand-framing into SHA3-256 in
  `xtask`; generation fails unless both agree.

## Regenerating and checking

    cargo xtask vectors            # rewrite all files
    cargo xtask vectors --check    # exit 0 only if everything matches

`--check` (1) regenerates every file in memory and byte-compares it with the
file on disk, (2) re-derives every stored vector from its stored seed and
inputs and reports differing fields, and (3) independently re-verifies vector 0
of every suite from its stored full-hex objects: decapsulation of the stored
ciphertext with the stored secret key, verification of the stored signature,
opening of the stored sealed box, every negative vector, and the combiner
recomputed from stored inputs.

The secret keys in these files are derived from published seeds and are
therefore not secret. Never use them, or `DeterministicEntropy`, for real keys.
